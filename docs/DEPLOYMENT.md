# Deploying Formatted Translator

This guide takes you from zero to a running instance on Cloudflare Workers,
connected to your own translations repository.

## What you need

- A **public GitHub repository** holding the translations (see
  [Repository layout](#repository-layout) below).
- A **Cloudflare account** (the free Workers plan is enough).
- Node.js 20+ and npm.

## 1. Create the GitHub App

One GitHub App provides both sign-in (OAuth) and commit rights. Go to
GitHub → *Settings* → *Developer settings* → *GitHub Apps* → **New GitHub App**:

| Setting | Value |
|---|---|
| App name | anything, e.g. `my-project-translator` |
| Homepage URL | your deployment URL |
| Callback URL | `https://<your-domain>/auth/callback` — add `http://localhost:3000/auth/callback` as a second callback for local development |
| Expire user authorization tokens | leave on (the user token is used once and discarded) |
| Request user authorization (OAuth) during installation | **on** |
| Webhook | **off** (uncheck "Active") |
| Repository permissions | **Contents: Read and write** — nothing else |
| Where can this app be installed? | Only on this account is fine |

After creating it:

1. Note the **App ID** (on the app's General page).
2. **Generate a client secret** — note it.
3. **Generate a private key** — a `.pem` file downloads.
4. **Install the App** (left sidebar → Install App) on the account that owns the
   translations repo, restricted to that one repository.

GitHub's key is PKCS#1; the Workers runtime can only import PKCS#8. Convert it once:

```sh
openssl pkcs8 -topk8 -inform PEM -nocrypt -in downloaded-key.pem
```

Keep the output for the next step (the whole block, including the
`-----BEGIN PRIVATE KEY-----` lines).

## 2. Configure

Point the app at your repo in `wrangler.jsonc`:

```jsonc
"vars": {
	"GITHUB_REPO": "your-org/your-intl-repo",
	"GITHUB_BRANCH": "main",
	"SOURCE_LOCALE": "en"
}
```

Set the five secrets (paste the multi-line private key as-is when prompted):

```sh
npx wrangler secret put GITHUB_APP_ID
npx wrangler secret put GITHUB_APP_PRIVATE_KEY
npx wrangler secret put GITHUB_OAUTH_CLIENT_ID
npx wrangler secret put GITHUB_OAUTH_CLIENT_SECRET
npx wrangler secret put SESSION_SECRET        # 32+ random characters, e.g. `openssl rand -base64 33`
```

## 3. Deploy

```sh
npm install
npm run deploy        # vite build && wrangler deploy
```

Add a custom domain under the Worker's *Settings → Domains & Routes* in the
Cloudflare dashboard (or a `routes` entry in `wrangler.jsonc`), and make sure the
GitHub App's callback URL matches the final domain.

### First-run checklist

1. Open the app — the locale list should render (works even before secrets are
   right, via unauthenticated reads).
2. Sign in with GitHub — you should land back on the app with your avatar in the
   header. Failure redirects to `/?login=failed`; check the App ID / client
   secret / callback URL.
3. Save one string in a test locale. Verify the commit on GitHub: *author* is
   you, *committer* is `<app-name>[bot]`, the diff touches only that key.
4. If you use a roster, remove yourself temporarily and confirm saving is
   refused.

## Local development

```sh
cp .dev.vars.example .dev.vars    # fill in real values, or leave dummies
npm run dev                       # http://localhost:3000
```

With dummy secrets everything read-only works (browsing, counts, editor,
preview) — the app falls back to unauthenticated GitHub reads. Sign-in and
saving need real App credentials and the localhost callback URL registered.

`npm run test` runs the pure-logic tests; `npm run check` typechecks
(`worker-configuration.d.ts` is regenerated by `npm install` / `npm run cf-typegen`).

## Repository layout

Formatted Translator works against any repo shaped like this:

```
repo/
├── en/                  ← SOURCE_LOCALE: read-only in the app, defines the key set
│   ├── common.json
│   └── workshop.json
├── cs-CZ/               ← one directory per target locale
│   └── common.json      ← same file names as the source locale
└── translators.json     ← optional roster (see below)
```

- Module files are JSON maps of message key → ICU message string. Values may be
  nested objects of strings; keys may contain literal dots. Files containing
  non-string leaves (arrays, numbers) are shown but marked *GitHub only*.
- Files named `index.json` are ignored (treated as build artifacts).
- Top-level directories named `scripts` or `.github` are not locales.
- A missing module file in a target locale simply means "everything
  untranslated" — the app creates the file on first save.

### Roster (`translators.json`)

Optional file at the repo root controlling who may save:

```json
{
	"octocat": ["cs-CZ", "sk-SK"],
	"maintainer": "*"
}
```

GitHub login → allowed locales, `"*"` for all. **No file → anyone who can sign
in may translate.** The file is enforced server-side on every save; it's public
(the repo is public), which doubles as a credits page.

### Context notes (GitHub Wiki)

Enable the repo's wiki. Conventions:

- One page per module, named exactly like the module: page `common` for
  `common.json`.
- Inside, one `## full.message.key` heading per string; everything until the
  next heading (markdown, images) renders beside that string in the editor.
- The `Home` page renders as the app's *Help* page — document your project's
  tone/terminology there, plus these conventions.

A typo in a page name or heading silently orphans the note — the app shows
"Add context" as if none existed.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `atob() called with invalid base64` in logs, all writes fail | `GITHUB_APP_PRIVATE_KEY` is not PKCS#8 or got mangled — redo the `openssl pkcs8` conversion and re-put the secret |
| "GitHub App is not installed on …" | Install the App on the account owning `GITHUB_REPO` |
| Sign-in loops to `/?login=failed` | Callback URL mismatch, wrong client ID/secret, or clock skew; check the Worker logs (`wrangler tail`) |
| "not on the roster" when saving | Add the GitHub login to `translators.json` (or delete the file to open translation up) |
| Slow/failing reads while logged out locally | Unauthenticated GitHub API rate limit (60/hr/IP) — configure real App credentials |
| Save fails with per-key ICU errors | The translation drops a `{placeholder}` the source has, adds an unknown one, or has broken ICU syntax — the error names the key |
